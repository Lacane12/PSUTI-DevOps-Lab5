# Подготовка к защите

## Как коротко рассказать о работе

"Я сделал интерфейс афиши для варианта 3. Пользователь выбирает жанр, диапазон дат и цену билета. Фронтенд передаёт параметры в готовый API, который фильтрует, сортирует и разбивает результат на страницы. Всё окружение запускается одной командой `docker compose up -d`. В Compose три сервиса: база с PostGIS, готовый бекенд и Nginx с фронтендом. Данные базы сохраняются в отдельном томе."

## Что написано в README

README заменён инструкцией к готовому приложению. В нём есть требования, команда запуска, адрес приложения, работа с фильтрами, описание сервисов и команды остановки. Также объяснено, как поменять порт, посмотреть логи и пересобрать фронтенд.

На защите нужно понимать разницу между `down` и `down -v`: первая команда сохраняет данные в именованном томе, вторая удаляет их. Отдельно указано, что пароль уже созданной базы не меняется от редактирования `.env`.

## Разбор compose.yml

| Поле | Что означает в этой работе |
| --- | --- |
| `services` | Список сервисов приложения. Каждый запускается в отдельном контейнере. |
| `image` | Готовый образ. Для базы используется PostGIS, для бекенда образ автора задания. |
| `build: ./frontend` | Собрать образ фронтенда по Dockerfile из указанной папки. |
| `environment` | Передать переменные окружения внутрь контейнера. |
| `POSTGRES_*` | Настройки создания базы и пользователя при первом запуске пустого тома. |
| `PG_*` | Настройки подключения бекенда к этой базе. Имена переменных взяты из документации API. |
| `PG_HOST: db` | Адрес базы внутри сети Compose. `db` разрешается встроенным DNS Docker. |
| `SEED_MODE: sample` | При первом запуске добавить демонстрационные данные. |
| `${APP_PORT:-8085}` | Взять значение из окружения или `.env`. Если его нет или оно пустое, использовать 8085. |
| `ports` | Перенаправить порт компьютера на порт контейнера: слева порт компьютера, справа Nginx. |
| `volumes` у `db` | Подключить именованный том к каталогу данных PostgreSQL. |
| `volumes` в конце | Объявить именованный том, которым управляет Docker. |
| `healthcheck` | Регулярно выполнять команду, которая проверяет готовность сервиса. Код 0 означает успех. |
| `depends_on` + `service_healthy` | Дождаться успешной проверки зависимости перед запуском следующего сервиса. |
| `restart: unless-stopped` | Перезапускать остановившийся контейнер, если пользователь не остановил его явно. |

У базы `pg_isready` проверяет, принимает ли PostgreSQL подключения. У бекенда Python обращается к `/health/ready`: этот адрес сообщает готовность после инициализации базы. У фронтенда `wget` проверяет, что Nginx отдаёт HTML.

`interval` задаёт частоту проверки, `timeout` ограничивает её длительность, `retries` задаёт количество последовательных неудач до статуса `unhealthy`. В течение `start_period` сервису даётся время на инициализацию: неудачные проверки пока не расходуют лимит.

В команде базы используется `$$`: Compose передаёт один знак `$` в контейнер, чтобы переменные подставила оболочка контейнера. Без экранирования Compose попробовал бы подставить их заранее с компьютера.

Сеть отдельно не объявлена, поскольку Compose создаёт общую сеть по умолчанию. База и бекенд доступны внутри неё по именам сервисов. Только Nginx имеет опубликованный порт.

Тег бекенда содержит SHA коммита. Это фиксирует выбранную сборку исходников и защищает от незаметного перехода на новую версию через `latest`. Версии Nginx и PostGIS указаны тегами веток; их патчи могут обновляться. Для полной фиксации всех образов используют digest `sha256`.

## Как проходит запрос

```text
Браузер -> localhost:8085 -> frontend (Nginx)
                               |
                               | /api/v1/events?...
                               v
                         backend:8000 -> db:5432
```

Браузер загружает HTML, CSS и JS из Nginx. JavaScript запрашивает `/api/v1/meta/genres` для справочника жанров и `/api/v1/events` для списка. Nginx передаёт запросы `/api/` в бекенд. Бекенд выполняет запрос к PostgreSQL и возвращает JSON.

В `proxy_pass http://backend:8000` нет завершающего `/`, поэтому сохраняется весь путь `/api/v1/events`. Браузер обращается к тому же адресу, с которого загружена страница, поэтому для такого подключения не требуется CORS.

## Параметры API

| Параметр | Назначение |
| --- | --- |
| `genre_code` | Код жанра из серверного справочника. |
| `starts_from` | Начало диапазона, включительно. |
| `starts_to` | Конец диапазона, не включительно. Фронтенд передаёт полночь следующего дня. |
| `price_min`, `price_max` | Цена билета в рублях, обе границы включаются. |
| `sort=starts_at` | Сначала ближайшие события. |
| `sort=-starts_at` | Сначала более поздние события. |
| `sort=price_rub`, `sort=-price_rub` | Цена по возрастанию и убыванию. |
| `page`, `page_size` | Номер страницы и число записей. |
| `include=venue,artist` | Добавить информацию о площадке и исполнителе. |

Бекенд возвращает записи в `data`, а общее количество после фильтрации в `meta.total`. Фильтры передаются вместе, поэтому работают одновременно. Сортировка выполняется до пагинации. Даты передаются с часовым поясом `+03:00`, время в карточках также показывается по Казани.

## Частые вопросы

**Чем образ отличается от контейнера?** Образ содержит файлы и настройки запуска. Контейнер является запущенным экземпляром образа со своим состоянием.

**Для чего нужен Docker Compose?** Он описывает несколько связанных сервисов, их настройки, сеть, тома и порядок запуска в одном YAML-файле.

**Почему используется PostGIS?** Это требование готового бекенда: его схема поддерживает координаты и географические запросы. Обычного образа PostgreSQL без расширения недостаточно.

**Почему `localhost` нельзя указать как `PG_HOST`?** Внутри контейнера это адрес самого контейнера. База находится в другом, поэтому нужен адрес `db`.

**Что делает `-d`?** Запускает контейнеры в фоне и возвращает управление терминалу.

**Нужен ли `--build` при первом запуске?** Нет, Compose соберёт отсутствующий образ фронтенда. После изменения файлов фронтенда нужен `docker compose up -d --build`.

**Что делает Dockerfile фронтенда?** Берёт Nginx, копирует его конфигурацию и статические файлы приложения. Node.js для запуска не нужен.

**Почему файлы не подключены через bind mount?** Они уже находятся в образе. Для запуска не нужна отдельная синхронизация папки с контейнером, но после изменений образ нужно пересобрать.

**Почему нет отдельной сети в YAML?** Общая сеть создаётся Compose автоматически. Сервисы находят друг друга по именам.

**Почему порты базы и бекенда не опубликованы?** Фронтенд обращается к бекенду по внутренней сети, а бекенд так же обращается к базе. С компьютера нужен только порт Nginx.

**Достаточно ли обычного `depends_on`?** Он задаёт порядок запуска, но не ждёт готовности приложения. Поэтому используется условие `service_healthy`.

**Перезапустится ли контейнер из-за статуса `unhealthy`?** Сам по себе этот статус не вызывает перезапуск. `restart` срабатывает при завершении контейнера. `depends_on` также не является постоянным мониторингом зависимостей.

**Останутся ли данные после пересоздания контейнера?** Да, пока сохранён том. После `docker compose down -v` том удаляется.

**Почему смена пароля в `.env` может сломать подключение?** При непустом томе PostgreSQL не создаёт пользователя заново. Бекенд начнёт использовать новый пароль, а в базе останется старый. Нужно вернуть прежний пароль или изменить его в самой базе. Удалять том можно только если данные не нужны.

**Что с безопасностью пароля?** Значение по умолчанию рассчитано на локальную учебную работу. `.env` исключён из Git, а база не имеет опубликованного порта. Для реального окружения нужен отдельный подход к секретам.

## Что показать преподавателю

1. Выполнить `docker compose config --quiet`, затем `docker compose up -d` и `docker compose ps`.
2. Открыть приложение, выбрать жанр и цену, показать изменение списка.
3. Выбрать один день в обоих полях, показать события именно за этот день.
4. Переключить сортировку на "Дешевле" и "Дороже".
5. Показать "До: 0", отсутствие результатов и сброс фильтров.
6. Открыть `compose.yml` и объяснить сервисы, порты, зависимости и том.
7. Показать `docker compose logs --tail=30 backend` и объяснить разницу между `down` и `down -v`.

Если спросят про проверки кода: `npm test` запускает проверки параметров API и граничных дат. Node.js нужен только для этих проверок, не для запуска приложения через Docker.
