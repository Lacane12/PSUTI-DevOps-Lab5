# Лабораторная работа 5. Вариант 3

Афиша Казани с фильтрами по жанру, датам и цене билета. События можно сортировать по дате начала и цене в обоих направлениях.

## Запуск

Нужны Git, Docker с плагином Compose и интернет для загрузки образов. В Windows должен быть запущен Docker Desktop в режиме Linux containers.

В папке репозитория выполните:

```bash
docker compose up -d
```

При первом запуске Docker соберёт фронтенд, а бекенд создаст таблицы и добавит демоданные. Откройте [http://localhost:8085](http://localhost:8085). Если контейнеры ещё запускаются, проверьте их состояние командой `docker compose ps`.

## Как пользоваться

1. Выберите жанр, начальную и конечную даты, минимальную и максимальную цену. Любое поле можно оставить пустым.
2. Нажмите "Найти события". Обе даты входят в диапазон, время указано по Казани (МСК).
3. В списке "Сначала" выберите сортировку. Она применяется ко всем найденным событиям.
4. Используйте кнопки "Назад" и "Дальше" для перехода между страницами. Кнопка "Сбросить фильтры" возвращает полный список и сортировку по ближайшей дате.

Чтобы найти бесплатные события, укажите 0 в поле цены "До". В карточках видны цена, площадка, время и статус события.

## Что запускается

В `compose.yml` описаны три сервиса:

- `db`: PostgreSQL 17 с PostGIS 3.6. Данные хранятся в томе `postgres_data`.
- `backend`: готовый образ [nelkor/kazan-events](https://github.com/nelkor/kazan-events), закреплённый по коммиту. Код бекенда не изменялся.
- `frontend`: Nginx со статическими HTML, CSS и JavaScript. Отдаёт страницу и проксирует `/api/` в `backend:8000`.

Compose создаёт общую внутреннюю сеть. На компьютер опубликован только порт фронтенда. Бекенд ждёт готовности базы, фронтенд ждёт готовности бекенда. Это проверяется через `healthcheck` и `depends_on`.

Параметры по умолчанию подходят для локальной лабораторной. При необходимости скопируйте `.env.example` в `.env` и измените `APP_PORT` или `POSTGRES_PASSWORD`. Менять пароль лучше до первого запуска: существующий том сохраняет старый пароль базы.

## Полезные команды

```bash
docker compose ps
docker compose logs --tail=100 backend
docker compose logs --tail=100 frontend
docker compose down
```

`down` останавливает контейнеры и удаляет сеть, данные базы остаются. Команда `docker compose down -v` удаляет также том и все данные. При следующем запуске бекенд создаст демоданные заново.

После изменения фронтенда выполните `docker compose up -d --build`.

Если порт 8085 занят, задайте другой `APP_PORT` в `.env` и повторите запуск. Документация API доступна по [http://localhost:8085/docs](http://localhost:8085/docs), проверка готовности по [http://localhost:8085/health/ready](http://localhost:8085/health/ready).

Если Docker пишет "Virtualization support not detected", проверьте виртуализацию в BIOS/UEFI: "SVM Mode" для AMD или "Intel Virtualization Technology" для Intel. Для WSL 2 также нужны компоненты Windows "Платформа виртуальной машины" и "Подсистема Windows для Linux". После их включения нужна перезагрузка. Подробности в [документации Docker](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/topics/).

Разбор конфигурации и вопросы для защиты находятся в [docs/defense.md](docs/defense.md).
